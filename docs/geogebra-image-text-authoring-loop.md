# GeoGebra 图片＋文本素材构建闭环

## 目标

把公开 GeoGebra 作品作为**研究样本**，学习其中的题意表达、动态机制与几何构造；最终由模型根据题图和题面文本生成原创 FamTutor 文档，而不是复制外部作品。

## 五层产物

1. **来源层**：主页 URL、作者、公开资源 ID、标题、日期、引用关系和 SHA-256。
2. **观察层**：题面文本、缩略图、关键帧、可操作控件和状态变化；原始文件只保存在仓库外的研究目录。
3. **语义层**：年级、章节、知识点、已知/求证、几何对象、约束、交互意图和教学阶段。
4. **能力层**：将复现所需机制映射为现有原子接口、可组合 Macro 或真实能力缺口。
5. **原创层**：独立编写 FamTutor Case，经过双渲染器、确定性时钟、断言和视觉验收。

## 处理顺序

### 1. 完整采集

- 使用官方公开 API 按 24 条分页，直到最后一批少于 24 条。
- 递归展开 `book → chapter → page`，不能只统计主页卡片。
- 保存 Activity/Book 元数据；下载其引用的 `.ggb`、预览图和缩略图到仓库外目录。
- 以资源 URL 去重并记录哈希，采集过程支持断点复用。
- 不执行 GGBScript 或 JavaScript。

### 2. 图片＋文本联合理解

每个题目形成统一的 `semantic brief`：

- `curriculum`：年级、册别、章节、知识点；
- `prompt`：题面、条件、目标、分问；
- `scene`：点、线、圆、多边形、函数图像、文本与布局关系；
- `constraints`：共线、垂直、平行、全等、相似、轨迹等；
- `interaction`：可拖点、滑杆、按钮、显隐、动画阶段；
- `evidence`：题图区域和元数据/构造命令的可追溯证据；
- `ambiguities`：仅凭图文不能确定的含义，禁止静默猜测。

图片负责回答“画面中是什么、在哪里、状态如何变化”；文本负责回答“为什么这样构造、要求证明或探索什么”。`.ggb` Manifest 只作为第三路结构证据，不替代题意理解。

### 3. 能力反推

按以下优先级处理：

1. 已有原子命令直接组合；
2. 多题重复、语义稳定的组合沉淀为 Macro；
3. 缺失且跨题复用的几何/控制机制新增底层原子接口；
4. 仅服务单题的差异留在 Case 参数中，不进入底层。

新增底层能力必须满足：定义清楚、参数最少而充分、跨渲染器一致、可验证、可被模型从名称与说明正确选用。

## 验收门槛

- **结构**：所有引用存在，依赖图无环，约束与断言通过。
- **渲染**：Direct SVG 与 JSXGraph 语义一致；文本避让、角标、线宽和颜色符合视觉基础方案。
- **交互**：确定性时钟下关键帧可复现；拖拽/控制动作不改变数学不变量。
- **教学**：初始状态不过度泄题；交互步骤与题意一致；结论能由操作或证明到达。
- **来源**：原创 Case 不携带外部原始文件；研究证据保留 URL、ID 和哈希。

## 批量推进策略

先按知识点和机制聚类，再从每簇选择“最小代表题、典型题、边界题”三类样本。一个簇只有在三类样本均可复现时，才视为能力覆盖；单个截图相似不等于能力完成。

## 参数化旋转不变量基础方案

当题图包含“手拉手、旋转、共顶点、等顶角”等结构时，优先使用以下组合，不新增题型专用命令：

1. `scalar.slider(theta)` 提供有界旋转参数；范围必须排除使关键交线重合或交点退化的状态。
2. `transform.rotate_point(source, center, angle: theta或固定角)` 生成旋转关联点；同一不变量链共享同一安全表达式参数。
3. 用 `polygon.vertices`、`segment.through_points`、标准边刻线和角弧表达已知与对应关系，避免颜色代替数学标记。
4. 用 `equal_length`、`equal_angle` 验证全等条件，再用测量断言验证固定交角、垂直或等长结论。
5. 除默认态外，至少在参数定义域内选择 5 个分散样本做确定性 sweep；每个样本都必须重新完成文档求值和全部不变量断言。

若上述组合已能表达运动、渲染和验证，就把它沉淀为 authoring pattern；只有多个独立题目反复需要同一复杂 DAG，且组合本身具有稳定领域名称时，才考虑上升为 Macro。

## 路径点不变量与安全定义域

当题目要求点在线、射线、线段或圆上运动时，优先组合 `point.on_path` 与已有几何原子，不为“动点题”增加专用命令：

1. 从题意中明确完整数学定义域和排除点；交点重合、零长度向量或角退化必须记录为语义边界。
2. Gallery 的可拖路径应限制在能完整求值的安全子区间；安全区间不改变待研究不变量，只避免用户误入题目已排除的状态。
3. 至少取路径两端和三个内部位置重新求值并验证全部断言，不能只检查默认截图。
4. 若必须展示退化边界，使用独立阶段或条件反馈明确说明“未定义”；不得把未定义数值伪装为 0 或继续显示结论成立。
5. 多个独立资源出现相同的安全域裁剪需求前，保持为 authoring pattern，不新增 bounded-glider 等冗余协议。

## 全等判定的刚体副本方案

当资源用“拖动第二个三角形”说明 SSS、SAS、ASA 或 AAS 时，拖放区域只是演示交互，不是判定定理的一部分。优先采用：

1. 用一个基础三角形作为语义源，第二个三角形由 `transform.rotate_point` 和 `transform.translate_point` 生成，确保运动本身严格保持长度与角度。
2. 每个案例只显示该判定需要的三项标准标记：边用 `marker.segment_tick`，角用 `angle.three_points`；不同刻线数量表达不同对应组。
3. 使用有界旋转滑块改变副本朝向，并在至少五个角度重新验证对应长度和角度。
4. `PointIn`、`If`、`Vertex` 等若只服务自由摆放、状态选择或对象索引，应映射到既有交互、阶段和显式实体，不据此新增底层几何接口。
5. SSS/SAS/ASA 共享的是 authoring pattern，而非新的“全等三角形”原子；只有未来需要从条件自动求解未知顶点时，再评估通用约束求解能力。

## 参数函数性质探索方案

当资源通过滑杆研究一次函数、二次函数或其他参数函数的图像性质时，优先复用以下组合：

1. 用 `scalar.slider` 表达函数参数和采样自变量，用 `function.explicit` 表达可写成 `y=f(x)` 的图像；只有无法显式化且在多类资源中重复出现时，才评估参数曲线原子。
2. 用表达式点把采样值绑定到函数，用简短虚线或投影辅助读取坐标；不得创建在合法边界参数下会退化为零长度的装饰线段。
3. 用布尔表达式与条件可见性切换“增大、减小、常值”“开口向上、开口向下、非二次”等互斥反馈；较长的定义和推理放入阶段 narration。
4. 对函数类别的边界参数显式建模：例如 `k=0` 是常函数，`a=0` 使 `y=ax²` 不再是二次函数。不得仅为保持截图好看而缩窄参数域。
5. 至少选取正、负、零参数及多个采样位置做确定性 sweep，并验证采样点在图像上、截距/顶点和对称关系成立。

若 `CurveCartesian` 能无损映射到 `function.explicit`，或 `Stretch` 只用于演示布局，应记录为映射结论，不扩大底层协议。

## 动态 n 边形与对角线方案

当题目要求边数 `n` 动态变化时，不在 Case 层预建多套多边形并用显隐切换：

1. 用整数 `scalar.slider` 提供 `n`，用 `polygon.regular` 构造有界规则多边形，并显式声明 `maxVertices`。
2. 用 `polygon.diagonals` 取得全部对角线，或用 `fromVertex` 取得一个顶点发出的对角线；返回值是可统一渲染和计数验证的 `segment2` 集合。
3. 分阶段展示轮廓、单顶点分割和全部对角线，避免高边数时视觉过密。
4. 对 `n=3`、中间值和最大值做 sweep，验证单顶点数量 `n−3`、总数 `n(n−3)/2`；超过边数或集合上限必须失败关闭。

来源中的 `Sequence`、`First` 只作为结构证据；若领域原子已表达题意，不照搬外部列表操作链。
