## 2. 本章视觉语言

第三章的核心视觉载体是数轴，不是坐标系。所有案例遵循同一语义：

1. 基线承担顺序与尺度，只使用中性色。
2. 解集使用强调色，覆盖在基线上方，不能与轴本身混为一条线。
3. 严格不等号对应空心端点；含等号对应实心端点。
4. 单侧无界区间用箭头明确方向；有限区间显示两端的开闭状态。
5. 多个条件分别占据独立轨道，公共部分在第三条结果轨道显示，避免把多条线完全压在一起。
6. 候选值使用可移动点或滑块，并以条件文本实时反馈“满足/不满足”。
7. 乘负数时把“数的位置关于 0 反向伸缩”和“不等号方向翻转”同步呈现，不能只更换符号。
8. 文本不压线；端点值位于数轴下方，条件与结论位于轨道左侧或画布上方。

建议基础视觉 token：

| 语义 | 颜色/样式 |
|---|---|
| 数轴基线、刻度 | `#6F7F8C`，1.4–1.7 px |
| 当前解集 | `#D06A3A`，2.8–3.2 px |
| 第二条件 | `#2E6DB2`，2.2–2.6 px |
| 公共部分/正确状态 | `#0E8378` 或 success token，3 px |
| 不满足/冲突 | danger token |
| 空心端点 | 白色/画布色填充，描边沿用解集色 |
| 实心端点 | 解集色实填 |

## 3. 底层能力审计结论

现有运行时已经具备：安全数值/布尔表达式、标量滑块、表达式点、线段与射线、条件文本、阶段活动、数值断言和 JSXGraph/Direct SVG 双后端。

但是，仅用二维几何点、线段和射线拼装数轴解集存在真实的语义缺口：

- 开/闭端点不是普通几何点的偶然样式，而是区间是否包含边界的数学语义。
- 无界端点、有限端点和空集需要统一的数据模型。
- 不等式组需要在多个轨道上复用同一类区间，并让渲染器在两套后端保持一致。
- 当前 `graphics2d.axes` 在 Direct SVG 中不提供教材所需的刻度标签和箭头语义，不能作为可靠的数轴协议。

因此应新增一个小而完整的 L0 原子：`interval.from_bounds -> interval1`。它只定义一维区间集合，不承担解方程、不承担求交、不绑定某个案例；渲染位置由通用参数 `y` 给出。建议参数：

| 参数 | 类型 | 定义 |
|---|---|---|
| `lower` | number 或安全表达式，可省略 | 下界；省略表示负无穷 |
| `upper` | number 或安全表达式，可省略 | 上界；省略表示正无穷 |
| `lowerClosed` | boolean，默认 false | 是否包含有限下界 |
| `upperClosed` | boolean，默认 false | 是否包含有限上界 |
| `y` | number 或安全表达式，默认 0 | 绘制轨道的纵坐标，不改变区间数学值 |

约束：`lower <= upper`；当两界相等时，仅两端都闭合才表示单点集，否则为空集。两个渲染后端都必须支持有限段、左右无界射线、全实数、单点和空集；空心/实心端点和箭头必须一致。

数轴基线、刻度和值标签仍可由现有点、线段、文本原子组合，不另造一个重量级“数轴组件”。这保持了接口的原子性：`interval1` 表达集合，已有几何原子表达参照系。

## 5. 每个案例的验收证据

每个案例都保留四类证据：

1. 来源证据：印刷页、PDF 页、图号、逐页视觉审阅状态。
2. 数学证据：区间值、断言、代表性边界与内部/外部测试值。
3. 交互证据：滑块或拖动事件、条件反馈状态、阶段切换不修改文档 revision。
4. 渲染证据：Direct SVG 静态渲染、render bundle、JSXGraph 浏览器截图与控制台无错误。
